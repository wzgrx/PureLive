# 沿用直播间的回放模式

已确认的本地设计：outputs/purelive-replay-existing-shell-20261103，使用frontend-design、art-direction，并以实际直播间横竖屏截图作为基底；40项网页原型检查仅证明设计交互，不替代原生功能。

| 原界面 | 本轮增加 |
|---|---|
| 页头/播放器/纯音频/投屏/小窗 | 原组件保留，进入回放时不更换原播放器外壳 |
| 视频底部原控制栏 | 上方增加进度和时间；横屏增加紧凑回放动作 |
| 信息栏/原画质与线路 | 用真实回放名称和日期替换直播热度，增加倍速与目录 |
| 下方原标签 | 增加回放，B站分P与同主播场次放在原内容区域 |
| 原RoomPanel | 倍速和目录按原竖屏底部、横屏右侧放置 |
| 原FloatingRoom/RoomMiniWindow | 同一运行时与会话，保留播放进度、速度和暂停意图 |

真实公开回放源仍由各平台ArchivePlaybackController负责。ownsSession默认true保留旧使用；原直播间传false，最终原生资源由RoomRuntime唯一拥有。普通直播无回放对象时走原逻辑。共享兼容ArchivePlayerPage仅委托核心LivePlayPage，避免保留第二套UI；该薄兼容入口有意引用核心页面，未将平台解析移入界面。

独立回放目录在新播放前等待旧浮窗资源退役；直播间选择目录仅返回metadata给原控制器。投屏/复制使用回放当前播放源，分离音轨不能伪装成可直接外播的完整单URL。直播录制与新独立窗口尚不支持录制回放/重建完整回放目标，入口不得误播或误录实时直播。
